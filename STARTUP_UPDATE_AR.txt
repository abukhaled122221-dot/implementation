تحديث تشغيل THIQA — تعليمات الفريق

فك محتويات هذا التحديث داخل مجلد imp نفسه (بجانب server وagents وdatabase)، ووافق على استبدال run-website.bat.
لازم يكون ترتيب الملفات:
imp/run-website.bat
imp/scripts/start-thiqa.ps1

أرسل التحديث كاملاً، مو ملف BAT وحده. ما يحتاج الزملاء يعيدون تنزيل المشروع.
بعد التركيب شغّل run-website.bat بالنقر المزدوج.

المتطلبات:
Python 3.10 أو أحدث: https://www.python.org/downloads/
اختر Add python.exe to PATH عند التثبيت، ثم أعد فتح السكربت.
Node.js 22.13 أو أحدث: https://nodejs.org/
السكربت لا يثبت Python أو Node تلقائياً، لكنه يوضح النقص ويتوقف.
أول تشغيل قد يحتاج إنترنت لتثبيت مكتبات المشروع.

ما تغير؟
التحديث في ملفي التشغيل فقط. لا توجد تغييرات على الوكلاء أو التسعير أو قاعدة البيانات.
يتحقق من Python الفعلي ويتجاهل اختصار WindowsApps، ومن Node وSQLite والمكتبات.
ينشئ .venv محلية عند الحاجة ويثبت متطلبات Python فيها.
يستخدم npm ci عند نقص مكتبات Node، دون تحديث حزم المشروع.
يتوقف إذا فشل الإعداد، ولا يفتح المتصفح إلا بعد جاهزية الخدمات الثلاث.
يعيد استخدام الخدمات السليمة، ولا يقتل برنامجاً يشغل منفذاً آخر.
يحفظ سجلات التشغيل والأخطاء في .runtime داخل imp.

وجود تبويبين طبيعي:
3000 = موقع ثقة.
8001 = منصة شركات التأمين التجريبية.
8000 = خدمة الوكلاء التي تعمل خلفهما.
لا تغلق نوافذ الخدمات أثناء استخدام المشروع.

عند ظهور خطأ: اقرأ رسالة نافذة التشغيل وسجلات .runtime/*.stderr.log.
للفحص فقط دون تثبيت أو تشغيل (من CMD داخل imp):
run-website.bat -CheckOnly -NonInteractive
للتشغيل دون فتح المتصفح:
run-website.bat -NoBrowser

اختُبر التحديث على ويندوز ببيئته العادية، وبمسار يحتوي مسافات؛ اشتغلت الخدمات الثلاث ورجع طلب تجريبي 16 عرضاً من 4 شركات. ونجح تشغيله مرة ثانية بدون عمليات مكررة. كما نجحت 4 اختبارات مركزة للسكربت.
